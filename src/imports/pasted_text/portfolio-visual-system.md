# Portfolio Visual System

Design this portfolio with a visual language inspired by industrial electronics, product manuals, technical labeling, modular hardware interfaces, and the playful precision associated with Teenage Engineering.

Do not directly copy any specific Teenage Engineering product or website.

The goal is to capture the underlying qualities:

* industrial
* modular
* information-dense
* playful
* extremely organized
* tactile
* slightly strange
* bold without being decorative
* functional graphics treated as visual design

This should NOT look like a conventional UX portfolio.

## Core idea

Treat the website like an oversized piece of equipment.

The page should feel built from large physical modules.

Each project is a giant horizontal information block spanning nearly the entire width of the browser.

Avoid floating cards.

Avoid small centered containers.

Avoid endless white space with tiny text sitting in the middle.

Think:

FULL-WIDTH MODULE

FULL-WIDTH MODULE

FULL-WIDTH MODULE

with strong graphic separation between them.

---

# Layout

Use a strong modular grid.

Desktop should use almost the entire viewport width.

Suggested page margins:
24–40px.

Do not constrain the entire site to a narrow 1200px centered column.

Information should frequently stretch from the left edge of the layout to the right edge.

Use large rectangular sections.

Each project should occupy a substantial portion of the screen.

A project module might contain:

PROJECT NUMBER

PROJECT TITLE

DESCRIPTION

CATEGORY

TOOLS

YEAR

STATUS

LARGE IMAGE / VIDEO / INTERACTIVE PREVIEW

LIVE ↗

GITHUB ↗

These should be arranged like technical information rather than a marketing card.

# Typography

Typography should feel utilitarian and engineered.

Use:

* neutral grotesk sans serif
* monospace where appropriate
* numerical labels
* compact uppercase technical text
* oversized headings

Avoid trendy luxury editorial serif fonts.

Avoid soft startup typography.

Create dramatic scale differences.

Examples:

96–160px project titles

12–14px metadata

18–24px body text

The hierarchy should feel almost excessive.

Large text can run close to the edges of its container.

---

# Borders and structure

Use visible structure.

Thin black rules.

Occasional heavier dividers.

Rectangular outlines.

Internal grid divisions.

Boxes should look structural rather than decorative.

Do not use rounded cards everywhere.

Most corners should be square.

Small radius values can appear occasionally where something should feel like a physical control.

---

# Color

Base palette:

OFF-WHITE
BLACK
CHARCOAL

Then introduce only 1–2 accent colors.

The accent colors should feel like markings on industrial equipment.

Examples:

* safety orange
* electric yellow
* signal red
* saturated cobalt
* acid green

Use them sparingly.

Color might indicate:

* project number
* status
* interaction state
* tiny labels
* active controls
* hover state

Do not turn every project into a different rainbow card.

---

# Imagery

Project visuals should be huge.

Avoid placing screenshots inside fake browser windows unless necessary.

Let screenshots crop aggressively.

Allow imagery to span entire columns or entire screen width.

Consider:

[ TEXT INFO ][ HUGE IMAGE ]

or

[ HUGE IMAGE ACROSS ENTIRE SCREEN ]

followed by

[ DATA ][ NOTES ][ LINKS ][ DETAILS ]

Treat project screenshots almost like product photography.

---

# Interaction language

Interactions should feel mechanical rather than cinematic.

Good:

* instant state changes
* tiny rotations
* sliding labels
* number counters
* switches
* underlines
* expanding information trays
* cursor-responsive details
* scroll-driven changes
* subtle snapping
* tiny UI sounds if appropriate
* buttons that visibly depress

Bad:

* floating blobs
* smooth generic fade-ups everywhere
* slow parallax
* excessive easing
* giant spring animations
* bouncing
* glassmorphism
* cinematic page transitions

Motion should feel like operating something.

---

# Buttons

Avoid generic rounded CTA buttons.

Buttons can look like:

* labels
* keys
* hardware controls
* rectangular toggles
* bordered text
* numbered controls

Examples:

[ LIVE ↗ ]

[ SOURCE ]

[ 01 ]

[ OPEN PROJECT ]

Use visible hover states.

A button should feel pressed or activated rather than simply glowing.

# Navigation

Keep navigation visible but unusual.

It could resemble:

* mode selectors
* tab labels
* numbered sections
* device controls

Example:

[ 00 INDEX ]
[ 01 WORK ]
[ 02 ABOUT ]
[ 03 INFO ]

Keep it extremely usable.

Do not sacrifice clarity for novelty.

# Personality

The site should have moments of humor or unexpected interaction.

Examples:

* strange tiny status messages
* project status marked as "UNDER CONSTRUCTION"
* unusual mouse interaction
* tiny functional icons
* hidden details
* unexpected alignment shifts
* playful microcopy

Keep the humor dry and restrained.

---

# Responsive behavior

On mobile, preserve the modular language.

Do not simply shrink the desktop layout.

Stack information blocks vertically while retaining:

* borders
* project numbering
* metadata
* large typography
* strong divisions

Project titles should still feel oversized.

---

# Avoid

Do not make this look like:

* Behance
* Dribbble
* a SaaS startup
* a Notion portfolio
* a generic Framer template
* an Apple product page
* cyberpunk UI
* brutalism for the sake of brutalism
* generic Swiss design
* trendy luxury fashion branding

It should feel like a strange but extremely well-designed object.

---

# Most important rule

If something feels too plain, do NOT immediately add decoration.

First modify:

* scale
* density
* grid structure
* hierarchy
* typography
* information placement
* borders
* interaction

The visual identity should come from how information is organized.

Build the homepage around THREE enormous full-width project modules.

The projects should feel like the main physical components of the site.
